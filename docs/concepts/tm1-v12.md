# What's new in TM1 v12

TM1 v12, which IBM's documentation also calls **TM1 Database 12** and **Planning Analytics Engine**, is a rebuilt version of the TM1 engine. The core ideas in this chapter are the same as in v11: cubes, dimensions, rules, feeders and TurboIntegrator work the same way. What changed is mostly how the engine is deployed and how you connect to it.

!!! warning "Check IBM's release notes"
    v12 changes from release to release. For the authoritative list of changed and removed features, see the *What's new in TM1 12* section of IBM's Planning Analytics documentation.

## Where v12 runs

IBM provides TM1 v12 on two platforms:

- **IBM Planning Analytics as a Service**, which IBM hosts for you
- **Planning Analytics on IBM Software Hub** (formerly Cloud Pak for Data), which runs on your own Kubernetes or Red Hat OpenShift cluster

Unlike v11, v12 is not installed as a classic Windows service.

## Servers become databases

In v11, each model ran as its own **TM1 server** process with its own data folder.

In v12, a TM1 service hosts one or more **databases**. A database holds the same things a v11 server did: cubes, dimensions, rules, processes, chores and security. This book uses "database" throughout.

## The REST API is the only interface

v11 offered two programming interfaces: an older C API and the newer REST API. v12 offers only the **REST API**.

As a result, older client tools built on the C API do not work with v12. Among them:

- TM1 Architect
- TM1 Perspectives
- TM1 Web
- Performance Modeler

Instead you use **Planning Analytics Workspace** and **Planning Analytics for Microsoft Excel**, which both talk to TM1 over REST. Your own scripts and integrations use REST too. See the [REST API](../rest-api/index.md) chapter.

## Files live inside the database

A v11 server could read and write files anywhere its Windows account could reach, and TurboIntegrator processes often loaded CSV files from shared drives.

In v12, the files that processes read and write are stored in the database itself. You upload, download and manage them through the REST API or Planning Analytics Workspace. Processes that relied on the file system or ran operating system commands need to be reworked when you move them from v11.

## MDX differences

IBM's documentation notes significant differences between the MDX engines in TM1 11 and 12, and some TM1-specific MDX functions are no longer supported. If you are moving MDX subsets or views from v11, test them on v12.

## What stays the same

If you know v11, most of your knowledge carries over:

- cubes, dimensions, elements, hierarchies and attributes
- consolidations and weights
- rules and feeders
- TurboIntegrator processes and chores, apart from file and operating system functions
- users, groups and security rights
- sandboxes
